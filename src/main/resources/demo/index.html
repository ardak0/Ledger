What am I looking at?

Every transfer is two ledger entries that sum to zero. The database itself refuses anything else, so the big number above cannot change however hard you hammer the accounts underneath it.

Safe mode always locks the lower account id first, so a wait cycle is impossible and nothing deadlocks. Unsafe mode locks in request order: A→B and B→A each grab one lock and wait for the other. Postgres detects the cycle and kills one transaction.

A killed transfer fails, but rolls back completely. No money is created or destroyed and no half-written transfer survives; the number above stays put, and the global line stays at zero. Safe mode only buys liveness (transfers succeed instead of dying), not correctness.
